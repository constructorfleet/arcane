3. Align shared presentation rules and simple existing-resource behavior together. Preserve backend authorization and owning-node identity.

Every implementation PR updates the relevant rows, release metadata and QA evidence. Required checks and focused tests precede the normal Gitea squash merge. Do not start the dev stack without a user request. The main deployment is the live QA environment; it is updated by Harbor publication and SwarmCD.

## Wider-site audit

The twelve wireframes do not exhaust the application. Apply shared menu/header/terminology/label rules to other resource lists as appropriate, including Podman, registries, ports and backups. Preserve domain-specific actions and the Agents administration exception. Do not invent new table columns for unaudited resources.

## Source-management implementation boundary

Importing a discovered stack may require desired-spec reconstruction; Docker state cannot restore comments, anchors, author inputs or secret payloads. Show a reconstruction report. Saving/importing never deploys. Review conflicting imports before explicit replacement. Sync-from is read-only input; manual sync-to targets another repository, with an explicit branch/path. Deployment is a separate manual action or GitOps-owned operation.

## Validation ledger

Record commit/release, commands, results and runtime acceptance per implementation batch. Unit/build success does not establish authenticated UI acceptance, live attachment/failover correctness or large-fleet capacity. Deferred design items are listed in the contract; do not silently substitute implementation guesses.
