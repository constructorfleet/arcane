# Resource design contract

Approved design decisions from the resource navigation review, 27 November 2026. This document specifies acceptance; it does not assert that the application implements every rule. Release evidence and known gaps are recorded separately below.

The interactive wireframe is in [resource-navigation-contract.html](./output/resource-navigation-contract.html). Changes to presentation, navigation or relationship behavior must keep both specifications aligned.

## Shared contracts

| Contract                                  | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Identity                                  | Every relationship has a resource type, stable ID, cluster identity and, when node-local, verified node identity. A name is display text, never a join key across nodes or clusters.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Relationship kinds                        | Owned by, Uses / References, Used by, and Runs on are separate facts. An external network or volume can be used by a stack without being owned by it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Resolution                                | List menus, overview sections, tabs and contextual lists consume the same relationship definitions and resolution results. Column visibility, pagination and label text do not determine navigation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Destinations · agreed                     | Plural links open a scoped resource list in the current detail context. Create a missing tab when the relationship warrants it. Singular owner links open the identified resource. All resource name and singular owner links open Overview. Explicit plural resource links still open their scoped tabs. Add Overview where absent; Tasks continue using their owning service context rather than a new task detail page.                                                                                                                                                                                                                                                     |
| Headers · agreed                          | Name, operational status and actions. IDs, namespaces, driver, scope, node attachment and aggregate counts belong in Overview. No global-volume badge.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Overview sections                         | Resource details first; then Linked resources using explicit relationship labels; then existing domain details. Containers get Stack resources for service/stack ownership, distinct from network and mount attachments.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Task list history · proposed              | The main Tasks list excludes only tasks whose desired state and current state are both Shutdown by default. Apply this filter before counts, sorting and pagination. Retain retiring tasks while current state is Running, and retain Failed, Rejected and other diagnostic states even if desired state is Shutdown. Service Tasks retains shutdown history with explicit state filtering; this list preference never changes runtime inventory, scan eligibility or service desired/running counts.                                                                                                                                                                          |
| Task container navigation · proposed      | Offer Open container only for a verified currently running container: exact TaskID and container ID, verified node binding, successful current observation and authorization. A task container ID or current Running state alone is insufficient. Apply the same eligibility to the Container cell and Related resources. Missing, removed, stopped, forbidden or unverified containers have no navigation action; show an appropriate plain-text state in the cell. Service and stack links remain available. Revalidate at navigation; if the container disappears, present an inline no-longer-available state with return-to-task context instead of a generic error page. |
| List contract                             | Preserve useful at-a-glance columns. Service retains its Stack link. Task retains Service and Node information; Related resources prioritizes service and stack rather than node.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Column inventory · proposed               | The current preview includes a complete proposed field inventory for its 12 resources. Proposed defaults, All proposed columns and Columns selection render from that same inventory. Columns and cleanup specifies authority, visibility, presentation and sorting/filtering. Other application lists remain outside this column audit. Fixed parent fields are omitted in scoped tables; relationship tables declare their context-specific fields separately.                                                                                                                                                                                                               |
| Density and status · proposed             | Use stacked identity / image text and compact relative timestamps, preserving full identifiers and times in details. Combine complementary metadata, not different kinds of status. Node readiness and scheduling remain distinct. Task current / desired states share a cell but keep separate meaning and filters. Labels are excluded from every resource table, including optional columns. Replica shortage is red, positive target reached is green, zero-target and unknown are neutral; job modes need completion-aware treatment.                                                                                                                                     |
| Labels · agreed                           | Never render raw resource labels in list tables, scoped tables or mobile table equivalents: no default or optional column, stacked summary, badge dump or expandable label cell. Automation can generate large label sets and long values. Keep label inspection/editing in resource details and supported label filters independent of visible columns. Verified metadata-derived ownership/source fields remain valid; do not dump their underlying labels.                                                                                                                                                                                                                  |
| Cluster scale · agreed                    | No Nodes membership column in Networks. Node filters are independent of visible columns. Labels never appear in resource table cells. No unbounded arrays of nodes, consumers, tags, ports or IPAM entries in table cells, including optional columns. Use a bounded summary and a remainder count; keep full membership in details or a scoped list. Default lists must not trigger per-row cross-cluster fan-out. Enrichments need an explicit budget, query reuse and incomplete / unavailable states. A 200-node cluster must remain readable.                                                                                                                             |
| Node roles · proposed                     | Worker and Manager are colored tags. The elected manager additionally shows Leader; Role filtering offers Worker, Manager and Leader. Leader is derived from manager election state, never accepted as a new assignable Docker node role.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Networks Source column · proposed         | Add Source rather than Created by: provenance is not a human audit actor. Candidate values are a verified stack name, Docker for built-in engine networks, System for identified system-managed networks, and Unknown when provenance is not established. Stack names link to that exact stack in the correct cluster. External means explicitly referenced as external by a stack. Display it in that stack relationship context; it never means created outside Arcane and does not establish source or ownership.                                                                                                                                                           |
| Menu contract · agreed                    | Top-level View details opens Overview. Details submenu contains the resource’s other views. Separate Related resources submenu contains scoped resource lists and identified owners / consumers. Then edit/configuration actions, operational actions and destructive actions last. Omit empty submenus. Icons, accessible labels and ordering are consistent across table, grid and mobile.                                                                                                                                                                                                                                                                                   |
| Details versus Related resources          | History, metrics, logs, configuration, inspection and image attestations / vulnerabilities belong in Details. Tasks, networks, volumes, services, stacks and other identified resources belong in Related resources. Existing dialogs may remain dialogs, including image release notes. Container release notes and Commit remain removed.                                                                                                                                                                                                                                                                                                                                    |
| No duplicate navigation · agreed          | Every destination appears once within a row menu. Overview appears only as the top-level View details item and never inside Details. Other destinations appear under either Details or Related resources, never both. Compare canonical resource identity, scope and tab / dialog, not labels. The row name keeps its normal primary navigation; Resource row selection opens Overview. Omit View details for resources without Overview.                                                                                                                                                                                                                                      |
| Scope and return navigation               | Destination shows the source relationship and preserves selected cluster, node attachment when needed, filters and return path. A scoped list must not silently become a global list.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| States                                    | Resolved, absent, external reference, unavailable and forbidden are distinct. No owner is not a failed request. Failed resolution shows retry; permission-denied destinations are omitted. No guessed fallback links.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Counts and completeness                   | Counts come from relation-aware queries, not the current page of a list. Unknown or incomplete results show unavailable / partial, never zero.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Volume identity                           | Driver metadata and Docker scope never prove shared physical storage. Workspace and container links use verified active attachments; multiple node records remain distinguishable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Source and deployment separation · agreed | Importing, editing and saving update editable configuration only. Deployment is a separate manual action or delegated to GitOps. Sync-from and sync-to use separate repositories; no write-back to the source repository. See Stack source contract for the complete workflow.                                                                                                                                                                                                                                                                                                                                                                                                 |
| Images and security                       | Use the Images and security contract as the shared authority across Images, Security, dashboard, node-scoped inventory and service/task warnings. cf.106–108 supersede repository-wide grouping and copy selection. Proposed extensions are explicitly marked.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Change control                            | This relationship inventory and layout contract is approved for implementation. New relation links require a defined resolver, destination, permissions and states; no page-local inventions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

| Task → stack                             | Task.ServiceID → service labels → stack namespace                                                                 | Stack Overview                                                       | Do not split the task or service display name                                                                  |

| Service → networks                       | TaskTemplate / endpoint network IDs → inspected network details                                                   | Existing service Networks tab                                        | Existing ID-based network mapping                                                                              |

| Stack → networks / volumes               | Ownership labels / verified deployment declaration, plus references from its service specs; inspect exact targets | Proposed stack Networks / Volumes lists                              | Separate Owned and Referenced · external; volume rows retain node attachments                                  |
| Stack → secrets / configs                | Ownership metadata plus exact IDs referenced by stack services                                                    | Proposed stack Secrets / Configs lists                               | References do not automatically mean ownership                                                                 |
| Network → owner / consumers              | Network namespace label + verified cluster; service/task attachments by exact network ID                          | Owning Stack; existing Services / Tasks tabs                         | Reuse existing manager/cluster resolution                                                                      |
| Volume → owner / consumers               | Volume ownership metadata where available; service mounts and verified task/container attachment                  | Owning Stack when proven; using services and existing container list | Proposed owner/service links; no owner inferred from driver or a name prefix                                   |
| Node → local resources                   | Verified Swarm node ↔ registered connection binding                                                               | Scoped tasks and existing node-local resource views                  | Connection registration is transport, not the user-facing resource owner                                       |
| Secret / config → consumers              | Exact Docker reference IDs, same cluster                                                                          | Using services; owning stack only with ownership evidence            | Metadata only; secret payloads never appear                                                                    |
| Image → containers / services            | Canonical running artifact and platform → verified live observations → task ServiceID                             | Proposed scoped Containers / Services tabs                           | Aggregate replicas without node pickers; never resolve by tag alone or include unused cache                    |
| Compose project → containers             | Compose project identity and labels in its node context                                                           | Existing project Services view                                       | A Compose project is not a Swarm stack                                                                         |
| Running stack → editable source          | Saved source or exact stack service specifications and verified references                                        | Stack Source editor                                                  | Import does not deploy; reconstruction is a proposed feature                                                   |
| Source repository → editable source      | Explicit source repository, branch, directory and revision                                                        | Stack Source editor                                                  | Input-only direction; importing does not deploy or write back                                                  |
| Editable source → destination repository | Separate destination repository identity, branch and directory                                                    | Sync-to destination                                                  | Different repository from the source; deployment is manual or delegated to GitOps                              |

## Complete list column inventory

Default, optional and contextual fields share one contract. Labels are never selectable columns. Presentation may stack related metadata while retaining independent sort/filter semantics. Contextual fields appear only in the named parent view; omit fixed parent identity columns. Unknown or incomplete counts never become zero.
