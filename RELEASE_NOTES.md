# 3.0.1-cf.108

- Identify running image versions by normalized repository, immutable running registry digest, and platform. Keep Docker's engine-specific image IDs only for owning-agent operations; local images without a resolved registry digest use their local content identity.
- Display each running version as a separate image row with its own detail page and scan. Merge replicas of the same artifact across Docker storage backends, remove size ranges and version-count controls, and show one report rather than one report per Docker ID. Detail lookup binds the original owning observation before pagination, including when platform variants share an index ID.
- Count logical running artifacts in the Images header; label the separate physical storage total as all copies.
- Apply the running-image library to node-linked image lists too. Exclude stopped history and unused cache copies; retain retiring tasks while they actually run. Security Scan All deduplicates the same artifact across engine IDs. Reuse one authorized live copy internally for scan submission and its report; Harbor remains the primary scanner, with the existing local fallback.
- Flag replicated services that simultaneously run distinct task image references on the dashboard and in running-task error cells. Compare pinned digests rather than tag aliases, preserve Docker's own task errors, and clear the flag after convergence. This includes temporary mixed versions during rolling updates. Unresolved identical mutable tags cannot prove identical image content from Swarm task specs alone.
- Use the same running-reference and normalized platform selection for report reads and scan submission, including ARM variants; stopped-container references cannot override the running artifact.
- Bound and coalesce local immutable platform metadata reads with the existing cache infrastructure. Filter unused image inventory before report-summary queries and cross-agent transfer. Inventory and dashboard requests do not collect registry reports.
- Validation: owning image and Swarm race tests, frontend unit checks, full formatting and lint, and a native captured-inventory replay from all five live agents. The replay confirms two different Docker IDs collapse to one artifact row with five internal observations and exact detail resolution from every node. Native reads confirmed the reported size range came from storage accounting differences for the same deployed digest.
- QA #257 and #258 remain open for authenticated browser acceptance. Fleet-wide stored vulnerability totals, durable cross-agent scan coordination, and end-to-end capacity validation remain tracked in #256; this release does not establish those guarantees.
